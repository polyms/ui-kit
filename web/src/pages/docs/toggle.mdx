A two-state button that can be on or off. Use it for binary settings where the control itself reflects the state — like bold, mute, or favorite — and pair it with an icon for a compact, immediate-feedback action.

## Usage

```tsx
import { Toggle } from '@polyms/ui-kit'

const toggle = <Toggle aria-label='Bold'>B</Toggle>
```

`Toggle` and `ToggleGroup` bring their own classes. Pass the same `size` you use on `Field`, `Select`, and `Button` when they share a row so the heights stay aligned. `rounded` pills a single `Toggle` and a `ToggleGroup`. Omit `rounded` and the group shell keeps a small corner radius with a little padding inside the border.

## Sizes

Toggles and toggle groups come in 6 sizes, matching Field and Button. Leave `size` unset for the default step. Set `size` on `ToggleGroup` to size the shell and every toggle inside it.

## Controlled vs Uncontrolled

### Uncontrolled

Use `defaultPressed` to set the initial state and let the component manage itself:

```tsx
const toggle = <Toggle defaultPressed aria-label='Favorite' />
```

### Controlled

Drive the pressed state externally with `pressed` and `onPressedChange`:

```tsx
import { Toggle } from '@polyms/ui-kit'
import { useState } from 'react'

export default function ControlledToggle() {
  const [pressed, setPressed] = useState(false)

  return <Toggle pressed={pressed} onPressedChange={setPressed} aria-label='Mute' />
}
```

## Toggle group

Wrap related toggles in a `ToggleGroup` to share state. By default the group is exclusive (single selection, like a segmented control); pass `multiple` to allow several toggles to be pressed at once.

<CodePreview code={groupCode} testId='docs-preview-toggle-group'>
  <GroupStory />
</CodePreview>

Omit `rounded` to keep the small corner radius.

```tsx
import { Toggle, ToggleGroup } from '@polyms/ui-kit'

const toggleGroup = (
  <ToggleGroup aria-label='Alignment' defaultValue={['left']}>
    <Toggle value='left'>Left</Toggle>
    <Toggle value='center'>Center</Toggle>
    <Toggle value='right'>Right</Toggle>
  </ToggleGroup>
)
```

Pass `rounded` when the group should match pill fields and buttons on the same row.

```tsx
import { Toggle, ToggleGroup } from '@polyms/ui-kit'

const pillToggleGroup = (
  <ToggleGroup aria-label='Layout' defaultValue={['list']} rounded>
    <Toggle value='grid'>Grid</Toggle>
    <Toggle value='list'>List</Toggle>
  </ToggleGroup>
)
```

## Composition

`Toggle` composes with other primitives through the `render` prop. Inside a `Toolbar`, pass it to `Toolbar.Button` so it inherits roving keyboard focus. Pass `variant='toolbar'` on `Toggle` and `ToggleGroup` so they stay ghost toolbar controls. Without it, they use the form shell.

```tsx
import { Toggle, ToggleGroup, Toolbar } from '@polyms/ui-kit'

const toolbar = (
  <Toolbar>
    <ToggleGroup className='toolbar-group' aria-label='Alignment' variant='toolbar'>
      <Toolbar.Button render={<Toggle variant='toolbar' />} value='left'>
        Left
      </Toolbar.Button>
      <Toolbar.Button render={<Toggle variant='toolbar' />} value='right'>
        Right
      </Toolbar.Button>
    </ToggleGroup>
  </Toolbar>
)
```

## On a form row

Put `Toggle` and `ToggleGroup` beside fields and buttons. `items-end` lines the controls up when only the field has a label. Match `size` with the other controls. Pass `rounded` on `Toggle`, `ToggleGroup`, `Field`, and `Button` when that row is a pill. Leave `rounded` off the group to keep the small corner radius.

```tsx
import { Button, Field, Toggle, ToggleGroup } from '@polyms/ui-kit'

const filterRow = (
  <div className='flex flex-col gap-3 sm:flex-row sm:items-end'>
    <Field className='min-w-0 flex-1'>
      <Field.Label>Search</Field.Label>
      <Field.Control placeholder='Name or email…' rounded />
    </Field>
    <ToggleGroup aria-label='Layout' defaultValue={['list']} rounded>
      <Toggle value='grid'>Grid</Toggle>
      <Toggle value='list'>List</Toggle>
    </ToggleGroup>
    <Toggle rounded>Mine</Toggle>
    <Button rounded variant='primary'>
      Apply
    </Button>
  </div>
)
```

## Guidelines

- Always provide an `aria-label` (or visible text) so screen readers can announce the toggle's purpose.
- Prefer a Switch when the action takes effect immediately on a setting; use a Toggle when the button itself represents an on/off state (e.g. formatting tools).
- Give every `Toggle` inside a `ToggleGroup` a unique `value`.
- Use `multiple` for independent options and the default exclusive mode for mutually exclusive choices.
