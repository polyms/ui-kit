**Polyms UI Kit** is published on **GitHub Packages** as **`@polyms/ui-kit`**. After install you need **React 19+**, the **package styles**, and component imports from **`@polyms/ui-kit`**. For composition patterns (slate grays, compound components, CSS-only helpers) see [Design System](/design-system). The package also includes a **`ui-kit-skill`** installer for AI assistants (see [AI Agent Skill](/agent-skill)) — when in doubt, prefer **`index.d.ts`** for the version you installed.

## Configure the registry

The `@polyms` scope is hosted on **GitHub Packages**, which requires authentication to install — even though the package is public. Point the scope at the GitHub registry and add a token in a `.npmrc` at your project root (or `~/.npmrc`):

```ini
@polyms:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}
always-auth=true
```

`GITHUB_TOKEN` must be a GitHub **Personal Access Token** with the `read:packages` scope. Keep the literal `${GITHUB_TOKEN}` in `.npmrc` and export the secret in your shell or CI environment so the token never gets committed:

```bash
export GITHUB_TOKEN=ghp_your_token_here
```

## Install the package

```bash
pnpm add @polyms/ui-kit
```

```bash
npm install @polyms/ui-kit
```

```bash
yarn add @polyms/ui-kit
```

```bash
bun add @polyms/ui-kit
```

## Peer dependencies

Peers declared by the library:

- **`react`** ≥ 19.0.0
- **`react-dom`** ≥ 19.0.0

Install them at the app level (or let your workspace manage versions). They are not bundled into `@polyms/ui-kit`.

## Styles

Components rely on the CSS shipped with the package. You **must** load that stylesheet (or the Tailwind 4–compatible source entry) so layout, motion, and utility classes apply.

**Pre-built CSS** — the package root typically contains a file like **`styles-<hash>.css`** (the hash changes per release). Import it from `node_modules/@polyms/ui-kit/` according to your bundler (for example a single side-effect import in the client entry).

**Tailwind CSS 4** — if your app compiles Tailwind 4 with a compatible pipeline, you can consume **`@polyms/ui-kit/styles/tailwind.css`** (under the package `styles/` directory) so tokens and layers align with your own Tailwind setup.

If anything disagrees with this page, trust **`package.json` and the on-disk paths** under `node_modules/@polyms/ui-kit/` for your installed version.

## Import components

Use the **barrel export** only. Avoid deep imports such as `@polyms/ui-kit/button` unless your toolchain explicitly supports them.

```tsx
import { Button, Modal, Field } from '@polyms/ui-kit'
```

When unsure a symbol exists, open **`node_modules/@polyms/ui-kit/index.d.ts`** in the editor.

## Icons

Icons ship as a separate package, **`@polyms/icons`**, on the same GitHub Packages registry (released in lockstep with `@polyms/ui-kit`). Install it alongside React 19:

```bash
pnpm add @polyms/icons
```

```bash
npm install @polyms/icons
```

v1 exposes one style entry: **`@polyms/icons/bold-duotone`**. Export names are short — the style already lives in the subpath (`Home`, not `HomeBoldDuotone`). Each glyph is its own module, so importing one icon does not pull in the rest of the catalog.

```tsx
import { Home, Sun, setIconDefaults } from '@polyms/icons/bold-duotone'

setIconDefaults({ size: 20, secondaryOpacity: 0.4 })

export function Example() {
  return (
    <>
      <Home />
      <Sun size={24} color='var(--color-primary-600)' secondaryColor='var(--color-slate-400)' />
    </>
  )
}
```

Useful props: **`size`**, **`color`**, **`strokeWidth`**, **`secondaryColor`**, **`secondaryOpacity`**. Icons are decorative by default (`aria-hidden`); put the accessible name on the parent control for icon-only buttons. Global defaults live in a Zustand store via **`setIconDefaults`** / **`useIconStore`** — an explicit prop on an icon always wins.

Browse and filter the full catalog on the [Icons](/docs/icons) page.

## Imperative modals and Zustand

Using **`useModalStore`** with **`showModal`** / **`closeModal`** requires installing **`zustand`** in the host app (it is external to the library bundle). Mount **`Modal.Container`** once in your layout when using that flow. See the Modal docs page for the full pattern.

## Link locally for development

When developing against a local build, point your app's `package.json` at the built output folder:

```json
"@polyms/ui-kit": "file:./dist/ui-kit"
```

Adjust the relative path so it resolves from your app to the directory that contains the built `package.json` and assets.
